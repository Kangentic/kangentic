## What's New

- **Agents can set the browser viewport.** `kangentic_browser_set_viewport`, `_pop_out` and `_dock` let an agent check a responsive layout at a real desktop width instead of guessing from CSS. Three mechanisms sit behind them because the wrong one is silently wrong for a given surface: a real window resize for an offscreen or popped-out surface, device emulation for a docked pane. Every path reports the size it measured, never the size that was asked for.
- **Seven more browser tools.** `hover`, `scroll`, `select_option`, `drop_files`, `history`, `network` and `handle_dialog`, chosen from an inventory against chrome-devtools-mcp and playwright-mcp.
- **One browser surface per task.** The `isolated` option on `kangentic_browser_open_pane` is gone, along with the per-task lane limit. A task now has exactly one surface: the visible pane, or an offscreen one only when its project is in the background and no pane can mount. That offscreen surface lights the card globe and the Browser pill like any other, the task menu can close it, and opening the pill reclaims it on the page the agent left it on. Before this, an agent could finish a whole verification run in a lane with no browser on screen and nothing to close.
- **The drive cue moved onto the page.** While an agent drives the browser the terminal is no longer dimmed, because your keystrokes still reach it. The pane is the half that cannot take input, so it carries the veil, a breathing ring, a label and a pointer block, held for the length of the run rather than flickering per burst.
- **A GPU crash no longer leaves you with an app that will not start.** When Chromium runs out of GPU modes to try, it kills the browser process outright, with no dialog and no warning, and it can do that on every launch: all seven reported runs died within 12 seconds of starting and the user never got in. Every GPU death is now recorded at the moment it happens, and the next launch, finding a fatal one close to the previous run's last sign of life, starts in software rendering instead. That downgrade is a real setting, Settings > Performance > Graphics acceleration, turned off once and never turned back on for you, with a sticky toast saying what happened. Nothing here watches your driver version: we never established what killed the GPU process, so the app claims no cause and suggests no cure.
- **A Performance tab in Settings.** Graphics acceleration lives there, and Animations moved there from Board, where it never belonged. Memory's own hardware row stays put and is renamed Model acceleration so it reads distinctly from the graphics one.
- **The Agent Idle toast does something now.** The setting existed, defaulted on, and nothing in the app read it: picking Toast only produced no notification at all, and Both behaved as Desktop only. It raises when an agent finishes its turn or needs permission, and is suppressed when that terminal is already on screen in a task-detail window, the Agent Monitor, or a phone streaming it. That leaves it covering the case the desktop notification skips, where you are here and on this project but not looking at that agent.
- **The local model processes leave when idle instead of holding memory all day.** Dictation and embeddings each stayed resident for the life of the app once enabled, used or not. On a 9.6 hour session with both idle, dictation held 3.05 GB of Windows commit and embeddings 1.75 GB, together 75% of the app's commit footprint and the reason the low-memory warning fired on a machine with RAM still half free. Embeddings is no longer spawned until something needs it, and opening Quick Find in Smart mode warms it ahead of your first query. Dictation keeps only its small streaming worker warm, loads the larger accurate model on your first press, and recycles back to that baseline when it goes idle. Idle shutdown goes from 5 minutes to 30, shortening to 2 minutes on Windows once a worker passes 1.5 GB of commit. A press starts recording in 6 ms; the first one takes 894 ms to hand back its text while the accurate model loads under your utterance, and 32 ms after that.
- **A poster set ships with each release.** `demo-posters-<version>.zip` is attached to the release for the docs site's figures. It is not part of the installed app.

## Bug Fixes

- The usage dashboard counted a resumed conversation once per resume. The agent reports cost and duration as running totals for the whole conversation, but every `--resume` opened a new row and the reads summed them flat. On the dogfooding project that read $113,948 against a real $50,580, with one lineage repeating the same $22.16 across about twenty legs that did no work. Existing rows are backfilled on upgrade.
- Four more dashboard numbers were wrong on top of that: cost floated $758 above every breakdown it sat next to, both burn-rate lines divided a different ledger than the tiles beside them, Total Tokens summed context-window occupancy rather than consumption, and Avg Session summed wall clock per resume leg. Total Tokens now reports the four disjoint token types and says when its coverage starts later than the cost beside it; Avg Session is now Avg Active and names its denominator.
- A settings change that failed to save was silent. The single write-failure notice was normally spent on a window move nobody was thinking about, and every settings change after that was accepted by the panel and never persisted. The panel now raises its own notice, per setting.
- A failed config write names its cause. One hardcoded sentence used to cover a full disk, a permissions problem and a read-only volume alike, which do not have the same fix.
- Settings text fields commit on blur, Enter, or when the panel closes, instead of writing the whole config file on every keystroke.
- The low-memory toast stayed on screen indefinitely, asserting a number that could be hours old. It clears when headroom recovers, and a repeat replaces it instead of stacking.
- Toast cards no longer swallow clicks. A stacked toast physically covered the Save and Cancel buttons of any centred dialog and ate every click aimed at them, doing nothing at all, not even dismissing itself. It bit hardest while agents were running, because those toasts arrive constantly and stack three deep in exactly that corner.
- A toast on a hidden window could never finish leaving, so it stayed in the list forever. It now has a timer behind the animation.
- Error toasts carry a copy button, because an error is the one toast people need to paste somewhere else.
- A failed board-profile save reported success, printed it next to the store's own failure message, and closed the dialog on the lie.
- The Plan Complete toast fired for background projects, naming a task you could not see.
- A session that went idle and then crashed within the notification cooldown reported no crash at all.
- The first click on a fresh browser pane could open a native dialog that wedged the pane. Dialog interception is now in place before an agent can drive it.
- Electron drew a second dialog box of its own alongside the intercepted one, leaving a box on screen whose buttons did nothing.
- The browser Send tooltip said Ctrl/Cmd+Enter. Enter is what sends.
- Qwen worktree trust entries are cleaned up when the worktree is removed.
