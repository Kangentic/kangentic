# Display language and i18n

Kangentic's UI can run in the 15 languages VS Code ships language packs for (GitHub #489). The
conventions an author follows are in `.claude/rules/i18n.md`. This concept holds the design behind
them.

## Languages

`APP_LOCALES` in `src/shared/i18n/locales.ts` lists English plus zh-CN, zh-TW, fr, de, it, es, ja,
ko, ru, pt-BR, tr, pl, cs and hu, in VS Code's order, each with its own name (`LOCALE_NATIVE_NAMES`,
never translated). Every locale has a catalog from the first extract, but only `SHIPPED_LOCALES` reach
the user: the picker lists them and the first-launch suggestion offers only them. A locale joins that
list once its catalogs are translated, so a language never ships as an English UI under a foreign name.
Today the list is English alone, so the picker has one row and the first-launch suggestion never
fires. zh-CN carries only the six first-launch strings, seeded so the suggestion path has a real
translation behind it. Right-to-left languages are out of scope.

## Catalogs and owners

`lingui.config.ts` writes one PO file per area per locale, `src/locales/<locale>/<area>.po`:

| Area | Source | Owner |
| --- | --- | --- |
| `<folder>` | each folder under `src/renderer/components/` (`settings.po`, `dialogs.po`, `shared.po`...) | `settings`: #915. `dialogs`, `backlog`, `workflows`, `asana`, `onboarding`: #916. The rest: #917 |
| `src-renderer` | the rest of `src/renderer/`: root component files, hooks, stores, lib, utils | #917 |
| `src-shared` | `src/shared/`: the shared lists (keybindings, automation manifest, task template variables, pop-out titles, dictation and model labels) and the paired refusals | #915 |
| `src-main` | `src/main/`: native menus, message boxes, notifications | #917 |

The split is what lets the extraction tasks run side by side without editing one file. The source
roots take a `src-` name because a folder under `components/` is called `shared`, and two catalogs on
one file made `extract` and `check sync` disagree. `tests/unit/i18n-boundaries.test.ts` fails when
two catalogs share a file, and when a file that declares messages is in none or in two.

Origins name the file without a line number. With line numbers, an edit that only shifted a line in a
file holding a message changed all 15 locales' PO files (measured: one blank line made 15 files out
of sync), so every such PR failed the gate until re-extracted, and parallel branches conflicted in 15
files at once. A translator, or the translation harness, finds a message in its file by its text.

## Runtime

**Main** reads `displayLanguage` once, in `app.whenReady` before any window exists
(`initMainI18n`). A language that does not ship, or whose compiled catalog is missing, starts in
English, and the `[I18N]` log line says which. Its catalogs are the merged JSON `lingui compile`
writes to `.vite/build/locales/<locale>.json` (`catalogsMergePath`), because esbuild cannot import a
PO file. `scripts/build.js` compiles them strictly and `scripts/dev.js` beside its esbuild builds.

**Every window** is told the session's language on its command line (`--kangentic-locale=`, added by
both window factories), and preload hands it to the renderer synchronously
(`language.getBootLocale()`). Config arrives after the first render, so it cannot choose the catalog.
`src/renderer/index.tsx` loads the catalog, sets `<html lang>` (CJK glyph choice depends on it), and
renders inside `I18nProvider`, for the main window and every pop-out alike. English is bundled into
the entry and active from `catalogs.ts`'s first evaluation, so English never waits and I18nProvider,
which renders nothing without an active locale, can never paint blank. Every other locale is one lazy
chunk per area, which is also why the web demo carries English only.

**A placed value keeps its backslashes.** Lingui decodes `\xHH` and `\uHHHH` escape sequences
across a message's whole interpolated result, values included, so a Windows path such as
`C:\build\x64\app` in a placeholder came out as `C:\buildd\app`. Every I18n instance (the session's
in main and the renderer, the English one, and each extra locale instance) is wrapped at creation by
`guardPlaceholderBackslashes` (`src/shared/i18n/placeholder-backslash-guard.ts`), which stands each
backslash in a string value in for a private-use character until the translator has run. The
translation's own escape sequences still decode. `tests/unit/i18n-placeholder-backslash-guard.test.ts`
fails on an instance built without it.

The language never switches live: a change saves and restarts (`language.setLanguageAndRestart`,
the Graphics acceleration restart's path), because a reload would destroy every Browser pane guest.
Dates and relative times (`src/renderer/lib/datetime.ts`) format in the session's language, and
settings search matches the label, description, section and tab name as displayed, beside the English
keywords.

**Hot updates.** An edited `.tsx` keeps its new English until it is extracted: outside production a
missing message falls back to its source, which Lingui's message compiler fills. An edited PO file
would have reloaded the page, since only `catalogs.ts` imports it. `scripts/vite-lingui-catalog-hmr.mjs`
makes each PO module accept its own update and hand the messages to the renderer, which loads them
in place. `<Trans>` and `useLingui()` consumers re-render with them; text read through
`translateText` (settings and hotkey labels) changes on its component's next render.

## The Language setting

Settings > Language is the first System tab, so a reader who cannot read the rest finds it. Its one
card holds the shared Combobox: each shipped language by its own name and its lowercase code, the
current one checked (every combobox now draws that check, as ColumnPicker does). Picking another
asks to restart ("Switch to {language}?"), and only Restart now saves.

Kangentic always starts in English. Once, while the user has never chosen a language
(`hasAnsweredLanguageSuggestion`, a one-shot marker, because `save()` writes the whole config and a
key's presence cannot say whether the user chose), a persistent toast offers the OS language: the
most preferred of `app.getPreferredSystemLanguages()` that ships (`matchSystemLocale`), skipping one
with no translation yet. English counts as shipped, so a user who prefers English first gets no
toast. Its title and button are in the OS language, its body the same question
in English, and its button opens the restart prompt in the OS language, drawn through a second i18n
instance. Closing the toast, or either answer, records the marker. The prompt's six strings carry
their own `context`, so a copy of "Cancel" in another area cannot replace the translation.

## The catalog gate

A production renderer keeps only each message's ID, so a message missing from the catalogs renders
as a raw ID. `npm run i18n:check` (`scripts/i18n-catalogs.js`) runs `lingui check sync`, which fails
exactly when `lingui extract` would change a file, and `lingui check missing` for English. CI's checks
job runs it as its own step, and `scripts/build.js` (the release build) and `scripts/build-demo.js`
(the demo deploy) run it before building. Lingui 6 needs Node 22.19 or newer, and those scripts fail
loudly below it, since `release.yml` and `deploy-demo.yml` ask setup-node for `22`.

## Shared lists and their two audiences

The settings registry, the tab metadata and the shared lists (keybindings, the automation manifest,
task template variables, pop-out titles, dictation and model labels) hold their text as `msg`
descriptors, and their field types are `MessageDescriptor`. The hard-coded-text scan reads only
`.tsx`, so the narrowed type is what stops a new entry from landing as a plain English string:
`npm run typecheck` refuses one. A few types keep `LocalizedText` (`string | MessageDescriptor`,
`src/shared/i18n/text.ts`) because a plain string is a real value there: an option's protocol
token and a field's example URL in the automation manifest, the pop-out title resolvers, the
dictation language labels, the embedding gap name and a knowledge-graph field's `display`.

Much of that text has two readers. The renderer shows it in the session language with
`translateText`, while main writes the same words for an agent (MCP output, a run reason stored
for `kangentic_get_automation_runs`, the run log) and resolves them with `englishText`. A
`${descriptor}` in a template literal compiles and prints `[object Object]`, so every such reader
resolves first. Shared code that builds a sentence picks its translator one of two ways:
`automation-describe.ts` takes the `I18n` to speak with (`englishI18n` in main, the active `i18n`
in the Board Manager). `resolveSurfaceTitle` returns a `LocalizedText`, a knowledge-graph field's
`display` returns one or null, and `waitingLabel` returns `{ label, paused }` with `label` a
descriptor, each for the caller to resolve.

The preload imports no module that holds a `msg` descriptor. The runtime macro hashes message ids
with `node:crypto`, a sandboxed preload cannot load it, and a preload that fails to load leaves
`window.electronAPI` undefined, so the window renders nothing. The preload reads the pop-out
argument flag from `src/shared/pop-out-arg.ts` for that reason, and `pop-out.ts`, which holds the
titles, re-exports it for main. Only the E2E tier launches the real preload, so
`tests/unit/i18n-boundaries.test.ts` bundles it and fails on any `@lingui` input.

A refusal main throws stays English, because the renderer matches the thrown text exactly and the
phone and MCP read it too. Those refusals come in pairs from one wording: `WORKFLOW_REFUSALS` and
`WORKFLOW_REFUSAL_MESSAGES`, `workflowMoveRefusal` and `workflowMoveRefusalMessage`,
`resumeBlockMessage` and `resumeBlockRefusal`, `planApprovalLabel` and `planApprovalMessage`. The
English form is derived from the message through `englishText` when it is read, never at module
load, and only the message form is shown in the UI. An error main throws therefore still reaches
the renderer in English, as the raw error it was before.

## What stays English

- Agent and terminal output, which Kangentic does not write.
- Text main writes and the renderer shows as written: an error's reason in a toast body
  (`asSentence(describeIpcError(error))`), spawn progress labels, and a stall or wait reason in a
  notification. The renderer matches some of them back by their English (the git-queue check on a
  spawn label), so they would translate together with a structured way to read them, not one side
  at a time. `truncationNoticeText` stays English too: the transcript reader writes it into the
  entries an agent reads.
- The labels of Electron's own `role:` menu items (the macOS app, Edit and Window menus).
- Text an agent reads: MCP tool descriptions and results, agent prompts, template keyword names, and
  the reasons stored for `kangentic_get_automation_runs`. Code that builds it resolves a descriptor
  with `englishText` (`src/shared/i18n/english.ts`). The MCP handlers that write it are
  `automation-commands.ts`, `analytics-commands.ts` and `task-commands.ts` under
  `src/main/agent/commands/`. The warnings `apply-automations.ts` writes are not agent text: they
  reach the board's config warning banner, so they translate like any UI string.
- Template keyword syntax. A variable's `chip` and `DEFAULT_SPAWN_PROMPT_TEMPLATE` are syntax, not
  prose. The one description that names keywords literally, `task_xml`'s, quotes them for ICU.
- Seeded column names. They are persisted data, shared through `kangentic.json`, and matched by name
  in `search-commands.ts` and `apply-config.ts`. Other persisted defaults follow them: a new
  automation row's name (`New send message to agent`), a new shortcut's `New Action`, and the
  Shortcuts presets' app names, which a preset writes into the user's config.
- Refusals and errors main throws (see above), and the permission labels the agent adapters
  report, with their `DEFAULT_PERMISSIONS` fallback.
- The MCP tool manifest, which Settings > MCP Server also lists, by the extraction task's decision.
- The Text match placeholder and its wildcard patterns and samples: they stand for a line the agent
  writes. Only the rule names translate.
- Names: products, apps, agents, models, themes and licenses.
- Release notes and announcements, which arrive as written.
- Monaco's own strings, and Chromium's built-in ones: `electron-builder.yml` ships only Chromium's
  `en-US` locale pack.

## Limits

The one-line description budget in `settings-card-design.md` and the 900x600 toolbar spec measure
English. A longer translation can wrap or crowd a row they pass.

## Decision record

**Lingui over i18next** (chosen with the user, 2026-10-26). English stays inline in the components,
so the source reads as the UI. A message's ID is a hash of its English, so a reworded string is new to
every catalog, which is what lets a refill pipeline find what changed. PO files carry origins and
comments as context for translators and the translation model. The costs were accepted: a build plugin
in every Vite build and vitest, an extraction gate in CI and release, and `context` on ambiguous short
strings like Done, Merge and Open.

**The runtime macro for shared lists.** Main and preload are plain esbuild, where Lingui's
build-time macro does not bundle ("Could not resolve babel-plugin-macros"). Shared lists main imports
declare messages with `@lingui/core/runtime-macro`, which plain esbuild bundles, keeps the English on
each descriptor, generates the same IDs, and is extracted with `experimental.runtimeMacro`. The Vite
transform compiles it like the core macros. Rejected: explicit `/*i18n*/ { id, message }` descriptors,
whose hand-written IDs do not change with the English, and an esbuild plugin running Lingui's Babel
macro, which would bring Babel into the main build. The cost is an experimental API, so the Lingui
packages are pinned to an exact version. Every `.ts` module uses the runtime macro, renderer ones
included, because Playwright specs and the capture rig load `.ts` modules outside Vite.

**The shared-list proof is a keybinding main bundles, not one it reads.** No main file reads a
`KEYBINDINGS` label: main imports only `comboToAccelerator` (`ipc/handlers/system.ts`), and the
native menu labels in `src/main/index.ts` are literals, which the `src-main` extraction converts. So
`settings.toggle`'s label is the proof: `tests/unit/i18n-boundaries.test.ts` bundles `keybindings.ts`
with main's esbuild options and resolves it in English.

**Bundler module resolution.** Lingui 6 ships ESM only and its types only through package `exports`,
which `moduleResolution: node` ignores. `tsconfig.json` moved to `moduleResolution: bundler`, which
typechecked the whole tree unchanged and retired the `monaco-editor` path mapping that existed for the
same reason. A `paths` mapping to the `.d.mts` files was rejected because esbuild honours tsconfig
`paths` and bundled the type files.
