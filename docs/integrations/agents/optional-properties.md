# Optional adapter properties

| Property | Type | Purpose |
|----------|------|---------|
| `getSubmissionVerifier?(contextType)` | `(SubmissionContextType) => SubmissionVerifier \| null` | Returns a context-specific verification callback used in two flows: `'paste'` (post-`\r` confirmation in `TerminalSubmit.submitContent`) and `'command-injection'` (per-command confirmation in `TerminalSubmit.submitKeystrokes`, scheduled by `TerminalSubmitScheduler.scheduleKeystrokes`). The callback receives a `SubmissionContext` and returns `Promise<boolean>`. Adapters return `null` for contexts they cannot verify; every adapter returns `null` for `'paste'` today, falling back to the activity + data-floor backstops. Nine return a `'command-injection'` verifier: Claude (JSONL slash-invocation matching) and Codex, both VERIFIED and allowed to escalate; plus Copilot, OpenCode (via a read-only SQL query rather than a file read), Qwen, Kimi, Aider, Grok, and Antigravity (brain-dir transcript USER_INPUT matching), all CONFIRM-ONLY - they confirm and drive retry-on-Enter but are barred from escalation via `canEscalateOnVerificationFailure`. A verifier must only be added for an agent whose history is MEASURED to flush on submit; see [command-injection.md](../../architecture/automations/command-injection.md) and [Paste Engine](../../architecture/embedded-browser/browser-pane.md#paste-engine). |
| `liveTelemetryUnsupported?` | `AgentLiveTelemetryUnsupported` | Set when the agent CLI has no per-session telemetry channel (no status file, session history, or stream output integration is possible). Carries the renderer-facing label and tooltip so all agent-specific copy lives with the adapter. The task detail's context bar, the board card's footer and the Agent Monitor card's footer show it in place of a "Starting agent..." spinner that would never end. Currently used by Droid and Antigravity. |
| `reportsRateLimits?` | `boolean` | Set by adapters whose CLI streams account-wide rate-limit windows (plan-usage quotas). The renderer ContextBar shows its rate-limit pill for any session of such an agent, sourced from a shared global snapshot merged per window across sessions. Main's `RateLimitLedger` (`src/main/activity-engine/rate-limit-ledger.ts`) stamps every reported window with a reset `generation`, and the merge compares it between two reports of the same window, before their values. A fresh report that falls more than 5 points inside the same window is a free usage reset, and opens the next generation. A session still behind the current generation that falls the same amount catches up without opening another. A reset is either a session's own drop, or a new session's first report below the highest value the current generation has seen in that window, which the ledger keeps after the session that reported it is removed. The reset opens the next generation and replaces the held value, even though `resetsAt` did not move. A session that has reported nothing new since then keeps the older generation, so its stale pre-reset number is ignored until its next fresh report catches it up. Main also brings every such session's cached window up to the reset's value and re-sends it, so a renderer reload, or a board whose projects did not see the reset, shows it even after the session that saw it is gone. Within one generation, used-percentage only rises, so a sibling's stale cached report never regresses the displayed values, and a genuine window rollover is taken wholesale. A window whose `resetsAt` has passed is dropped, both when a report is merged and on the pill's 30-second tick, because Claude Code stops reporting a window once it resets and a sibling's last report of it would otherwise linger. A `resetsAt` of 0 means unknown and is kept. A freshly spawned terminal shows the same limits as its siblings before it has emitted its own status line. Omit (falsy) for adapters with no rate-limit telemetry. Currently set only by Claude. |
| `scopesTranscriptReadsByTime?` | `boolean` | Set when `transcriptToolCounts` and `transcriptToolResultTokens` honor `sinceMs` and `untilMs`, so a read holds exactly one run's calls even though the CLI writes every resume of a conversation to one transcript (Claude). Without it, the run-end count backfill skips a resumed conversation's later runs (a whole-transcript count would add the earlier runs' calls to this run's record), and the earlier-run Tokens fill does not read the agent's transcripts. |
| `pastedImageNativeExtensions?` | `readonly string[]` | Image extensions (lowercase, no dot) the CLI attaches natively when the file's path arrives as a bracketed paste. Kangentic saves a pasted-clipboard or dropped image to a file (reliable even where the CLI's own clipboard reader silently fails, e.g. Claude Code on Windows with Snipping Tool images - claude-code#26679) and delivers the shell-quoted path through xterm's `terminal.paste()`, the way a native terminal delivers a drop; a CLI that scans a paste packet for image paths then attaches the file inline in the user turn with no `Read` tool call. A plain string array, never a RegExp: the value crosses IPC in `AgentDetectionInfo`. Omit when the CLI attaches nothing from a pasted path. An image outside the set is re-encoded as PNG by the renderer and saved through `clipboard:saveImage` when the set includes `png`, so the set only needs to name what was verified to attach. Set by Claude (`png`, `jpg`, `jpeg`, `gif`, `webp`, its own `/\.(png\|jpe?g\|gif\|webp)$/i`, verified on 2.1.276), Gemini (`png`, `jpg`, `jpeg`, `gif`, verified on 0.60.0; a path with a space becomes an `@"..."` file reference instead of a chip), and OpenCode (`png`, `jpg`, `jpeg`, `gif`, verified on 1.18.30). Neither of those two was probed with webp, so a webp drop under them takes the PNG normalization, which attaches all the same. Probed negative on 2026-09-18, both quoted and bare, so left unset: Cursor 2026.09.10, Grok 1.0.0, Antigravity 1.1.13 (each inserts the path as text; Grok and Antigravity then open it with their own Read tool at submit). Not probed, since they could not reach a prompt on the probe machine: Codex (not signed in), Copilot 1.0.83 (the spawn fails with "No session, task, or name matched" for the session id the adapter passes), Qwen (not authenticated), Kimi (not logged in), Droid (not logged in), plus the uninstalled Aider, Oz, Ollama and Goose. The probe: spawn a session in a `/preview`, then `kangentic_devtools_pty_input` with `bytes` = base64 of `\x1b[200~"<absolute png path>"\x1b[201~`, and look for the chip; no submit is needed. |
| `pastedImageReferenceTemplate?` | `string` | Fallback text pasted for an image outside `pastedImageNativeExtensions` that could not be re-encoded as PNG (the bytes did not decode, or the set has no `png`), or for every image when that set is not declared (a typed path is inert text to most CLIs), so the agent reads an explicit instruction instead of a bare path. `{path}` is replaced with the shell-quoted absolute path; a template lacking `{path}` has the quoted path appended. Omit to paste the bare quoted path. Currently set only by Claude (`Read this image: {path} `, which now covers svg and any file whose bytes Chromium cannot decode). |
| `buildEnv?(options)` | `(SpawnCommandOptions) => Record<string, string> \| null` | Adapter-specific environment variables to inject into the PTY spawn. Three uses. Most implementers deliver MCP config an adapter cannot pass on the command line: either because the CLI has no MCP flag at all (OpenCode's `OPENCODE_CONFIG_CONTENT`, carrying the whole config), or because the value is a secret that must not land in argv or in a repo file (Codex and Droid both pass only `KANGENTIC_MCP_TOKEN`, referenced by name from their config). Grok extends the pattern furthest: its env carries the MCP URL and token (`KANGENTIC_MCP_URL` / `KANGENTIC_MCP_TOKEN`, dereferenced by grok's `${VAR}` expansion so its `.grok/config.toml` block stays fully static) plus `KANGENTIC_EVENTS_PATH` for the hook bridge's `env:` sentinel. Goose's native permission/autonomy control is an env var (`GOOSE_MODE`) rather than a flag, so its permission mode is delivered here. Claude's renderer variable, `CLAUDE_CODE_NO_FLICKER=1` (`rendererEnvironment`), is the third use. Implemented by Claude, Cursor, OpenCode, Codex, Droid, Grok, and Goose. |
| `getExitSequence?()` | `() => ExitSequenceStep[]` | Keys (and `{ delayMs }` pauses) to write to the PTY to ask the agent to exit. Default is `['\x03']` (Ctrl+C only). Claude overrides with Esc, a 400 ms pause, Ctrl+C and `/exit`. |
| `firstPromptMayBeTyped?(options)` | `(SpawnCommandOptions) => boolean` | Whether a fresh launch with no prompt opens the same interactive session, with its input box in the alternate screen, so a task's agent may start while its new worktree's setup script runs and get its first prompt typed in. Asked per launch. Claude only, on its fullscreen renderer. See [First prompt typed](adapter-interface.md#first-prompt-typed-firstpromptmaybetyped). |
| `consoleCloseIsGraceful?(platform)` | `(platform: NodeJS.Platform) => boolean` | Whether closing the agent's console is itself its graceful exit there, as measured. True means kill, suspend and quit close it at once and type nothing. Claude: Windows and Linux, not macOS. Default false. |
| `hungTurn?` | `HungTurnSpec` (`{ quietLimitMs, interruptKeys }`) | When a running workflow task's busy turn has hung, and the CLI's own interrupt that ends it, for the workflow hang check (`src/main/workflows/workflow-hang-check.ts`). The check reads the history's write time through `locateSessionHistoryFile` and `statSubagentTranscripts`. Declare it only from a measurement of the real CLI's longest healthy quiet. Claude: 20 minutes, twice its 10-minute cap on a foreground command (no healthy turn of 437 measured went longer), and Esc. Omitted: the agent's turns are not checked. |
| `mayApprovePlanTool?(toolName)` | `(toolName: string) => boolean` | Whether the adapter's plan tool approval hook may answer a permission prompt for this tool (see [`plan-approval-bridge.js`](bridge-scripts.md#plan-approval-bridgejs)). The plan approval gate holds such a prompt's permission idle for the hook's marker; every other prompt passes at once. It names candidates only; the hook decides from the session's own rules and, for a tool judged by input, from the call's input. Claude: any MCP tool but Kangentic's own, and its built-in `Artifact`. The hook leaves an `Artifact` delete to the user, and the gate shows that prompt 1 s late, after waiting for a marker that never comes. Default false. |
| `backgroundCommands?` | `{ source: 'hooks' \| 'session-history'; launchHint: boolean }` | The agent reports the background commands it starts, so a launch holds the session `thinking` until the command exits or the agent marks it a service, and its task sessions are offered `kangentic_mark_background_service`. `source` says where the starts come from (its hooks, or a history file its parser tails); `launchHint` says whether a launch also tells the agent how to mark a service. Read at spawn onto the session row (`ManagedSession.reportsBackgroundCommands`). Declared by Claude, Qwen, Gemini, Copilot, Grok, Kimi and Codex; the per-agent decisions are in [Background commands](background-commands.md#background-commands). |
| `attachSession?(context)` | `(SessionContext) => SessionAttachment \| void` | Per-session lifecycle hook for adapters that need work outside the declarative `runtime` strategy (out-of-band CLI queries, file watchers, etc.). The returned `dispose` is called on session end. |
| `summarize?(prompt, cliPath, cwd, options?)` | `(string, string, string, SummarizeOptions?) => Promise<string>` | One-shot summarization for the auto-name-tasks-from-prompt feature. Runs the title prompt on the Automation agent's model and effort in the shared answer home: through the adapter's own answer run where it was measured to title cleanly (Gemini, Copilot, OpenCode), and otherwise a headless print run (Claude's runs on its answer arguments with `--output-format json`). `SummarizeOptions` carries `model`, `effort`, `runDirectory` and `onUsage`, the sink that receives the run's `AgentCallUsage` for the `background_calls` ledger. Antigravity is the one PTY exception: `agy -p` hangs when stdio is not a TTY (upstream google-antigravity/antigravity-cli#318), so its summarize runs the print mode through a hidden PTY in a pre-trusted scratch cwd. Warp has no headless run and omits it. Aider, Ollama and Goose omit it too: each has a headless answer run (`answerFromContext`) but no summarize, and Aider's answer run is built from its published options without a run against an installed Aider. |
| `answerFromContext?(prompt, cliPath, cwd, model?, options?)` | `(string, string, string, string \| null?, AnswerFromContextOptions?) => Promise<string>` | One-shot, read-only answer for the Knowledge Graph. The prompt arrives fully built; the adapter chooses only its CLI flags and how to read the answer out of stdout. The prompt stays OFF the command line: an answer prompt runs to about 50k characters, past the Windows command-line limit, so it goes on stdin, or through `promptVia: 'file'` for a CLI that reads a file (Grok `--prompt-file`, Aider `--message-file`). `cwd` is the answer home, `<tmpdir>/kangentic-ask-home` (`kangentic-ask-home-<uid>` on POSIX, where the temp folder can be shared): one stable directory for every answer run, never the project. On POSIX it is created private to the user (0700), and an existing one is used only when it is a real directory the user owns and no one else can write to; otherwise a fresh private folder takes its place for the rest of the launch. The home and each run directory are handed over as their real paths: macOS keeps its temp folder behind a link (`/var` is `/private/var`), and a CLI that resolves its working directory keys trust and saved chats by the real one. Every agent CLI keys its own state by working directory (sessions, trust entries, project registries), so a fresh directory per question left one entry per question in each CLI's store. Per-run files (an MCP config carrying the token, a prompt file, a chat history) go in `options.runDirectory`, a fresh `kangentic-answer-*` directory removed after the run. `AnswerFromContextOptions.onUsage` receives the run's `AgentCallUsage` when the CLI reports one (Claude and Antigravity today), before an error result throws, since a failed run was still paid for. Each adapter also keeps its run out of the CLI's saved sessions: Claude passes `--no-session-persistence`, Codex `--ephemeral`, Qwen `--chat-recording=false`; Copilot, Cursor, Grok, Gemini and Antigravity remove their session by id afterwards, and OpenCode runs `session delete`. Every adapter except Warp implements it, since Warp has no documented read-only headless run. |
| `answerCapabilities?` | `AnswerCapabilities` | Declared beside `answerFromContext`: `streaming` (text reaches `onEvent` as it is written), `search` (the run honours `options.retrieval`, reaching `kangentic_search` through an MCP URL whose `answer-` caller segment makes the server expose that one tool and nothing else), `model` (the run takes a model id, which makes the agent's Model row in the Knowledge Graph card (Settings > Knowledge Graph) required), `effort` (the run passes `options.effort` as the CLI's own effort flag; the Knowledge Graph card shows its optional Effort row only when this is true and the CLI reports effort levels), and `defaultEffort` (the level an unset row runs at, shown as its placeholder). The handler passes the user's level, else `defaultEffort`, and either only if the CLI still reports it. Claude, Grok, Copilot and Antigravity declare `effort` with a `low` default; Claude's `low` also keeps extended thinking off, and a higher level lets the level decide. Claude, Grok, Copilot, Cursor and OpenCode declare `streaming` and `search`; Antigravity and Gemini declare `streaming` only. Antigravity's headless run denies any tool that needs approval, our search included. In the runs tried, Gemini's headless run never registered our MCP tool: in plan mode with the folder trusted in `~/.gemini/trustedFolders.json` (which a project's MCP servers need; `--skip-trust` does not do it) and the server marked `trust: true`, the server connected and the tool was "not registered"; default mode was tried only with the built-in tools narrowed to `read_file` (`tools.core`, which may itself filter MCP tools), with the same result. Asked to search, the model also handed the question to its own `codebase_investigator` subagent. Qwen, Codex, Kimi and Droid declare neither until a probe on a signed-in account passes: in 2026-09 Codex, Kimi and Droid were not signed in, and Qwen's configured provider rejected every request. Aider, Goose and Ollama were added as base runs (prompt in, reply out) and declare neither; Ollama's plain model run has no tools to search with. A search-capable run may call `kangentic_search` at most `ANSWER_SEARCH_BUDGET` (4) times per question; the server answers a further call with an instruction to answer from what it has, which is what stopped a Grok run making about 50 searches. Read generically by the answer handler and the Knowledge Graph settings tab, never by agent name. |
| `openAnswerSession?(input)` | `(AnswerSessionInput) => AnswerSession` | A warm answering process for one Knowledge Graph chat: started when the graph opens (an idle one makes no model call), asked turn by turn, and disposed when the chat ends, the graph closes, after 10 idle minutes, or on quit (`answer-session-pool.ts`, one live session at a time). Its presence is the capability. It keeps the same read-only flags as `answerFromContext`. The shared transport is `shared/answer-session/stdin-json-session.ts` (one JSON line per user turn, a turn ending on the CLI's result line); the adapter supplies the flags, the turn line, the reducer and the answer extractor. Measured on a 143k-character prompt at Sonnet: first text 2.2 s cold, 1.3 s warm, 0.8 s for a follow-up that sends only the new question. Claude implements it (`--input-format stream-json`). Claude's answer runs also pass `--no-session-persistence` and `autoMemoryEnabled: false`, without which every run left a project folder under `~/.claude/projects`. |
| `parseTranscript?(agentSessionId, cwd, place?, reportedPath?)` | `(string, string, CliPlace \| null, string \| null) => Promise<ParsedTranscript>` | Parse the agent's native session history into agent-agnostic `TranscriptEntry[]` for the MCP `get_transcript` structured format. The adapter owns all format/location knowledge (JSONL file, chat JSONL, SQLite DB), so `handleGetTranscript` never branches on agent name. Reads at most the most recent `MAX_PARSE_SOURCE_BYTES` (16MB) of the source, prepending a `truncated` system entry when it omits anything (see `parseTranscriptWindow` below for the unbounded walk). Must not throw; returns `{ entries: [], sourcePath }` on missing/corrupt history. Implemented by Claude, Droid, Codex, Gemini, Qwen, Kimi, OpenCode, Grok, Antigravity, and Cursor; Aider/Warp/Copilot/Ollama/Goose omit it (raw format only). See [get_transcript](../mcp-server/session-tools.md#kangentic_get_transcript). |
| `parseTranscriptWindow?(agentSessionId, cwd, startByte, maxBytes, attributedMessageIds?, place?, reportedPath?)` | `(string, string, number, number, Set<string>?, CliPlace \| null, string \| null) => Promise<ParsedTranscriptWindow>` | Parse ONE bounded byte window of the native transcript, retaining nothing between calls. `parseTranscript` returns only the most recent `MAX_PARSE_SOURCE_BYTES` of a large transcript (a whole-file read is what OOM'd the main process), which is right for a reader but would silently shrink the conversation INDEX to recent history only. The conversation indexer therefore walks with this instead: window by window from offset 0, chunking each window and dropping its entries, so the whole file is indexed while only one window is resident. Pass `nextByteOffset` back verbatim as the next `startByte`; the walk ends when it stops advancing or reaches `totalBytes`. `attributedMessageIds` is the walker's bounded usage-attribution carry, threaded through every window of one file: an agent that reports one API message's tokens on several transcript lines attributes them to the first line it emits, and a per-window dedupe attributes them AGAIN past a seam - invisible to chunking, but a double-counted turn in `conversation_turn_usage`, which keys a row per line uuid. Seed the dedupe from it, add what you attribute, prune it to a small bound before returning, and never reset it per window (a window can legitimately attribute nothing and still sit mid-message). Adapters whose usage is already one-per-line can ignore it. Implementations must NOT cache per-file state (a sweep touches every session, and retaining would evict the live viewer's hot parse state); the carry does not bend that, since it is the caller's and is not retained between calls. Implemented by Claude; adapters without it fall back to `parseTranscript` and index recent history only. It is also the only read that gives a turn end's reply its anchor (see [Automation triggers](../../architecture/automations/triggers.md#on-agent-turn-end)); without it, `transcript.finalReply` reads the newest reply in the transcript tail. |
| `readTranscriptPage?(agentSessionId, cwd, request, place?, reportedPath?)` | `(string, string, TranscriptPageReadRequest, CliPlace \| null, string \| null) => Promise<TranscriptPageReadResult>` | One page of the conversation's history for the Conversation viewer, which shows the tail `parseTranscript` reads and loads the rest as the reader scrolls. `request` reads before a cursor, after one, or around a position, at most `maxBytes` of source, never past `untilPosition` (the tail's start). Cursors are the adapter's own opaque strings; the tail's `truncated` notice carries the first one in `earlierHistory`, and every entry a pageable parser produces carries `origin` (its conversation and the position it starts at) so the viewer can place it on a scrollbar spanning the whole conversation. A page must mint exactly the entries a whole-file parse mints for its lines, the same uuids included: JSONL adapters share `readJsonlHistoryPage` (`agent/shared/jsonl-history-page.ts`) with their tail's line parser, and an adapter whose uuids number lines carries a line count in the cursor. A `probe` request (the timeline's) reads only times and positions, so a JSONL adapter skips that line count for it. Answers `reset` when the source was rewritten. Retains nothing between calls. Implemented by Claude, Qwen, Droid, Codex, Kimi, Gemini (JSONL only), Grok, Antigravity, Cursor, and OpenCode (local database only; its unit is the characters of stored data). An adapter without it is read as the tail alone, as before. |
| `transcriptHasTimestamps?` | `boolean` | False for an agent whose transcript records no timestamps: the viewer orders its entries by position, asks for no timeline, and shows no date while dragging the scrollbar. Declared by Grok and Cursor. Cursor's entries use `ts: 0`, so the message row shows no clock. Grok stamps parse time, and the row shows that clock. |
| `statSubagentTranscripts?(agentSessionId, cwd, place?, reportedPath?)` | `(string, string, CliPlace \| null, string \| null) => SubagentTranscriptSignature \| null` | Cheap staleness signature (`fileCount`, `totalSize`, `maxMtimeMs`) for a session's subagent transcripts, computed without parsing them. Separate from the main transcript's signature on purpose: a subagent writes to its OWN file, so the main transcript's mtime and size never move while a fan-out runs, and an indexer watching only the main signature would never see the subagent turns. Returns `null` when the agent keeps no subagent transcripts for the session (pruned, or it never fanned out). Implemented by Claude (`~/.claude/projects/<slug>/<agentSessionId>/subagents/`); paired with `parseSubagentUsage` below. |
| `parseSubagentUsage?(agentSessionId, cwd, place?, reportedPath?)` | `(string, string, CliPlace \| null, string \| null) => Promise<ParsedSubagentUsage>` | Parse a session's Task-tool subagent turns into agent-agnostic `SubagentUsageTurn[]` for the durable turn-usage ledger (`conversation_turn_usage`). The adapter owns all format and location knowledge, including how one API message's repeated records fold into a single turn. That fold is NOT shareable with the main-transcript parser: Claude's subagent files re-emit a message mid-stream, so the main path's first-record-wins rule undercounts subagent output by 30% while staying exactly right for the main thread, which is why this folds field-wise max per `message.id` instead. `directoryPresent: false` records a coverage gap (no subagent transcripts for this session) rather than a quiet period; `complete: false` marks a partial read, so the caller retries later instead of marking the session indexed. Also returns `spawnLinks`: the spawning calls made BY these subagents, which is what lets a nested subagent resolve to the subagent that spawned it rather than only to a depth number. Those links are collected independently of the usage fold, because a message the ledger skips (no `usage`, or all-zero counts) can still carry the `Task` call that created a child, and a link dropped there is dropped identically on every re-walk. Must not throw. Implemented by Claude (`src/main/agent/adapters/claude/subagent-usage-parser.ts`); adapters with no subagent concept omit it and the ledger carries main-thread rows only, as it always has. |
| `locateResumeHistoryFile?(agentSessionId, cwd, place?)` | `(string, string, CliPlace \| null) => Promise<string \| null>` | Where the agent CLI's own resume from `cwd` reads the conversation's history, for an adapter whose `locateSessionHistoryFile` finds files the resume does not reach. `migrateResumeCwdIfRenamed` uses it as its skip check, so a renamed worktree's history still moves when only Kangentic's readers can find it. Claude implements it as the cwd's slug and its parent folders' slugs, the reach measured on 2.1.312. Omitted: `locateSessionHistoryFile` answers both. |
| `proveConversationGone?(params)` | `({ agentSessionId, reportedPaths, cwd, place? }) => Promise<boolean>` | Prove that a conversation's history file is gone, so a resume of it starts a new conversation from a recap instead of failing with "No conversation found". Returns `true` only on proof; anything else returns `false`, and an omitted method means the check never reports a conversation gone. `reportedPaths` are paths the agent itself reported, never ones Kangentic derived. Implemented by Claude (`adapters/claude/conversation-gone.ts`). See [Resume](../../architecture/sessions/resume.md#a-resume-the-cli-cannot-serve-starts-fresh-instead). |
| `stopBackgroundSession?(options)` | `({ agentSessionId, cliPath }) => Promise<boolean>` | Stop the agent CLI's own background session holding the conversation, when one is running. Claude Code's `/bg` moves a terminal's conversation into a background session its supervisor runs outside the task's PTY, so a pause ends only the terminal's client and a `--resume` would run a second process on the conversation. Called before a resume (`reconcileResumeAgentSessionId`) and on a terminal transition before the leftover reap (`reapTaskLeftovers`, not gated on "Stop leftover processes"), and only when the session record's own SessionStart hooks show the conversation started there (`statusFile.parseSessionStart`'s `inBackgroundSession`), so an ordinary resume runs no CLI. A Command Terminal, which has no session record, calls it at its end (before its leftover reap) and before an Earlier resume, on `backgroundSessionOf` instead, never for a session a live terminal holds. Claude lists with `claude agents --json` (about 220 ms), matches `kind: background` and the full `sessionId` only, and stops with `claude stop <id>` (about 450 ms, measured on 2.1.316: SessionEnd ran, the process and its pty host exited, the conversation was kept). Never throws. Implemented by Claude (`adapters/claude/background-sessions.ts`). |
| `resolveResumableSessionId?(options)` | `({ agentSessionId, cwd, place? }) => Promise<string>` | The id a `--resume` reaches the conversation by. A conversation moved into a Claude background session continues under a new id whose transcript holds only its title and name until that session's first turn, and `--resume <new id>` then answers "No conversation found" (measured on 2.1.316). Claude returns the transcript whose `continued-in` record names the new id, following up to four links, and the id itself otherwise. A background session that has not written its own transcript yet counts as one with no turn. Called right after `stopBackgroundSession`, behind the same gate. Never throws. Implemented by Claude. |
| `backgroundSessionOf?(options)` | `({ agentSessionId, cwd, place? }) => Promise<string \| null>` | The id of the agent CLI's own background session the conversation moved into, by its files alone, or null: either the conversation is that session, or its own record says it moved on to it. The gate in front of `stopBackgroundSession` and `resolveResumableSessionId` where no session record holds SessionStart hooks: a Command Terminal's end and an Earlier resume (`ipc/helpers/command-terminal-background-session.ts`). Runs no CLI. Claude reads the `continued-in` record `/bg` ends the old transcript with: the conversation's own last `continued-in`, with no turn after it, names the session it moved on to (following a chain of moves), or another transcript in its folder names the conversation itself, searched from the folder the cwd maps to when the background session has not written its own transcript yet. Listing and searching a folder of 156 transcripts took 6 to 11 ms. The record outlives the session, so an id means it may still run there. Never throws.
